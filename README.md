# 消息聚合（astrbot_plugin_msg_aggregator）

把用户连发的几条消息**合并成一次处理**，避免重复的 LLM 调用和被切碎的上下文。

适用于：一口气把一句话拆成三条发、"先发图再补一句"、在群里连续 @ 机器人补充说明。

## 30 秒确认它在工作

装上后**不用改任何配置**，直接连发两条消息：

```
你: 今天天气怎么样
你: 我下午想去爬山
```

正常情况下，机器人只会回复**一次**，且它看到的是合并后的一句话（默认用换行连接）。
若它回复了两次，先看下面的「排查」。

想看统计与运行状态：打开 **WebUI → 插件 → 消息聚合**，详情页里有一个「运行状态」面板
（合并率、渠道分布、耗时分布、最近处理记录，以及当前正在缓冲的轮次）。

## 安装

把发布包（zip）上传到 AstrBot 的插件页安装，或直接放到
`<数据目录>/plugins/astrbot_plugin_msg_aggregator/`。

要求 AstrBot `>= 4.26`，**无第三方依赖**。

## 配置（一般不用动）

默认就是推荐值（`balanced` 预设：2.0 秒防抖 + 自适应）。需要调的话，三档预设覆盖绝大多数场景：

| 预设 | 防抖 | 自适应 | 适合 |
| --- | --- | --- | --- |
| `fast` | 1.0s | 关 | 追求最低延迟，能接受偶尔被切碎 |
| `balanced`（默认） | 2.0s | 开 | 绝大多数场景 |
| `patient` | 3.5s | 开 | 长段落、慢打字用户 |

几个值得知道的项（设置里有完整说明）：

- **自适应单次/总等待上限**：防止"用户一直发"导致永远不结算；
- **群聊中启用合并**：关掉后群聊消息完全不拦截；
- **感知输入状态**：仅部分平台（如 NapCat 的 `input_status`）支持，不支持时自动忽略；
- **过滤已撤回的消息**：仅部分平台投递撤回通知；
- **保留图文交错顺序**：默认关闭（默认结果是"所有文本 + 所有图片"）。

## 排查

| 现象 | 处理 |
| --- | --- |
| 消息没被合并 | 确认插件已启用；再看日志里有没有 `aggregate.start`（缓冲开始）与 `aggregate.flush`（已结算） |
| 一直不回复 | 检查「自适应总等待上限」是否被调得极大；或用户一直处于"正在输入"状态（有 `max_typing_wait` 兜底） |
| 群里不合并 | **这是平台限制**：未唤醒的群消息在唤醒阶段就被拦截，插件看不到。只有每条补充消息都 @ 机器人（或带唤醒前缀）才会合并 |
| 图片丢了 | 看日志 `attach.persist_failed`：临时文件复制失败且平台不支持 `untrack` 时会退化为 base64；4.26.5 就是这种情况 |
| 面板空白 | 需要较新的 WebUI（支持插件视图）。页面会自动回退到轮询；若连 bridge 都没有会明确提示升级 |
| 统计不准 | 面板里的耗时是**桶近似**（不是精确分位）；合并率 = 总条数 / 结算轮次 |

日志事件一览见 `docs/DESIGN.md` §19.1；统计口径见 §19.2。

## 开发

```
python tests/run_tests.py        # 107 项，离线、零第三方依赖
python build_zip.py              # 打包到 dist/
```

测试用 `FakeClock`，因此 12s/60s 这类用例毫秒级跑完；`FakeClock.advance()` 会先让出一轮
控制权再计算到期者——因为 `asyncio.create_task` 创建的协程要到下一个挂起点才真正登记。
